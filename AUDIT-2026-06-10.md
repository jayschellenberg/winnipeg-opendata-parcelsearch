# Repo Audit & Improvement Plan — Winnipeg Open Data Parcel Search
*Audited 2026-06-10. Analysis only; no code was modified. All file:line references verified against the working tree at commit `34947bf`.*

---

## 1. Executive Summary

**Overall health: B−.** The application code is genuinely good — defensively written, unusually well-commented, race-aware, with hard-won geometry lessons encoded — but it is undermined by repo hygiene and automation gaps that will eventually cost real data or real hours. The single biggest irony: a project with a 1,079-line replication guide has a README and LICENSE that belong to a *different product* (go-pmtiles), so the repo's front door misidentifies it. The `.git` directory is 609 MB because an 80 MB binary tile archive was committed seven times, and the repo lives inside Dropbox, which is already leaving corrupted temp objects in `.git`. A deliberate, well-reasoned network-retry fix was silently deleted by a later "simplify" commit and nothing caught it — because no CI runs the tests that do exist. The R data pipeline works but deletes files before rewriting them and never checks exit codes before its cleanup step, so one crash or one failed download can destroy the only local copy of a snapshot.

**Top 3 risks:** (1) data loss in the R archive pipeline (non-atomic writes + unchecked exit codes before deletion); (2) repo unsustainability — 609 MB git history in Dropbox, on a path to GitHub's 100 MB/file and practical clone limits; (3) silent regressions — the retry removal proves changes land without any automated gate.

**Top 3 opportunities:** (1) a half-day of CI + README/LICENSE fixes makes the repo trustworthy and self-verifying; (2) moving binaries out of git history shrinks the repo ~95% and removes the Dropbox/git failure mode; (3) extracting soda.js's pure join/merge functions into tested modules locks in the app's hardest-won correctness logic for ~a day of work.

## 2. Repo Map

**Purpose.** A free, client-only parcel-research tool for Winnipeg commercial appraisal work: search parcels by legal description or roll/address/zoning, view assessment + survey geometry on a MapLibre map with ~15 toggleable overlays (zoning, traffic, transit, policy areas, contaminated sites, historical as-of-date parcels), analyze sales CSVs, export CSV. Sister app of a Manitoba (non-Winnipeg) tool; this repo is the Winnipeg port. Maturity: a **production-deployed single-maintainer internal tool** (Vercel, live data, scheduled downloads) — not a prototype, not a multi-contributor product.

**Stack.** Vite 5 + plain ES modules (no framework), Tailwind v4, MapLibre GL 4.7, turf, pmtiles; data from Winnipeg Open Data's Socrata SODA API queried live by the browser; static GeoJSON/PMTiles assets in `web/public/`; historical shards served from a separate `wpg-parcel-history` repo via jsDelivr pinned to a commit SHA. Offline pipeline: R (sf) scripts + PowerShell scheduled tasks + a tippecanoe Docker image. No server, no database, no auth, no secrets.

**Architecture / data flow.**

```
Browser SPA (web/)
  index.html (594)  static shell: ~11 search inputs, ~16 overlay toggles, results table
  src/main.js (3,287)  entry: search flows, table render, sales tab, historical overlay, URL state
  src/soda.js (2,344)  data layer: all SODA queries, paging, caching (IndexedDB), joins, merges
  src/map.js  (2,224)  MapLibre setup: ~40 layers, popups, basemap toggle, measure tool
  src/lib/* (7 files)  reusable: chipInput, columns, tabs, infoIcon, urlState, format, sizeChange

        │ static assets (/transit-*.geojson, /parcels.pmtiles)
        │ historical shards (cdn.jsdelivr.net → wpg-parcel-history@<SHA>)
        ▼

  build_parcel_tiles.R + Dockerfile.tippecanoe → web/public/parcels.pmtiles

```

**Surprises found during mapping.** (1) README.md is go-pmtiles' README; LICENSE is Protomaps' BSD-2 (`LICENSE:1` "Copyright 2021 Protomaps LLC") — both evidently copied alongside `pmtiles.exe`. ## 3. Audit Report

Severity scale: **Critical** (act now) / **High** (real risk, soon) / **Medium** (worth fixing) / **Low** (note it). Each finding is labeled **[fact]** (verifiable at the cited lines) or **[judgment]** (my assessment).

### 3.1 The ugly parts (highest priority, cross-dimension)

**H1 — HIGH — Deliberate reliability fix was silently regressed.** [fact]
Commit `559f4f8` ("fetchSoda: retry 5xx + network errors with backoff") added a retry loop with a detailed rationale (Socrata's transient "Internal error: please include code <uuid>" responses). Commit `1348c06` ("Simplify chip input, columns, map, soda, and main") **removed it**; current `fetchSoda` ([soda.js:2130-2138](web/src/soda.js:2130)) is a bare fetch. Consequence: any single 5xx among the *dozens* of parallel paged calls a search fires (`fetchPerFeatureBboxUnion` batches, enrichment, overlays) fails that whole operation, for a failure class the commit history proves occurs in practice. Nothing detected the regression — which is the deeper finding.

**H2 — HIGH — 609 MB `.git`, binaries in history, git-in-Dropbox.** [fact]
`web/public/parcels.pmtiles` (82 MB) has been committed 7 times (`git log -- web/public/parcels.pmtiles`: `6c76c3d`…`bd34d6a`) ≈ 560 MB of history; `pmtiles.exe` (57 MB) is also tracked. `git count-objects` reports **zero packfiles** (everything loose) plus garbage `tmp_obj_*` objects — classic Dropbox-sync interference. Consequences: every clone/fetch moves ~0.6 GB; Dropbox continuously syncs git internals (the likely source of the corruption warnings); each future tile rebuild adds ~80 MB forever; GitHub hard-fails files >100 MB, so one fatter rebuild bricks pushes. The `.tmp.*` litter (e.g. `web/src/main.js.tmp.26460.*`, 18 stale `vite.config.js.timestamp-*.mjs`) is the same Dropbox/editor friction made visible.

**H3 — HIGH — The repo legally and descriptively claims to be go-pmtiles.** [fact]
[README.md:1-27](README.md) is the go-pmtiles README; [LICENSE:1](LICENSE) is Protomaps LLC's BSD-2-Clause. [REPLICATION_GUIDE.md:114](REPLICATION_GUIDE.md) says README should be "User-facing summary + live URL". Consequence: anyone landing on the repo (including future-you, or anyone you share it with) gets the wrong project name, wrong docs, and a license that grants rights you may not intend while leaving your own code's terms undefined. Two-file fix.

**H4 — HIGH — Pipeline can destroy the only copy of a snapshot.** [fact]
- [download_parcels.R:95](r/download_parcels.R): existing `.gpkg` is `file.remove`d before `st_write` — a crash mid-write loses the previous snapshot.
- Same delete-before-write in [build_historical_shards.R:214](r/build_historical_shards.R) and [sanitize_shards.R:49](r/sanitize_shards.R).
- [scheduled_download.ps1:27-30](r/scheduled_download.ps1) runs download → archive without checking `$LASTEXITCODE`, then the cleanup step deletes repo-dir `.gpkg` files (line ~39). The per-file "archived copy exists" check mitigates but doesn't verify integrity (no size/hash compare), and an archive script that exited non-zero after copying some files still lets cleanup proceed.
- [refresh_assets.ps1:44](r/refresh_assets.ps1): `git push` result unchecked — a failed push exits 0 and the refreshed assets silently never deploy.
This pipeline runs unattended twice a year in a hidden window with no failure alert ([setup_schedule.ps1:28-34](r/setup_schedule.ps1)); the failure you don't see is the one that costs the snapshot.

### 3.2 Architecture & design

**M1 — MEDIUM — main.js is a 3,287-line god module.** [judgment, sizes are fact]
[main.js](web/src/main.js) contains: both search flows, table rendering, CSV export, the entire sales-analysis tab (~600 lines), the entire historical overlay client (~420 lines), 10+ overlay toggle handlers, URL-state capture/apply, static-map compositing, and the parcel summary card. soda.js (2,344) and map.js (2,224) are similar single-files but more cohesive (one is "all queries", one is "all map"). The `lib/` extraction is good; main.js is where unrelated features still collide. This matches the Manitoba app's known pain point (REFACTOR_NOTES.md:266: "~5k lines… porting needs a careful pass").

**M2 — MEDIUM — Five-way manual column contract.** [fact]
Adding/removing a results column requires synchronized edits to: thead order in [index.html](web/index.html), cell-append order in `renderTable` ([main.js:2071-2120](web/src/main.js:2071) — the comment *documents* the constraint rather than enforcing it), `SORT_KEYS` ([main.js:163-193](web/src/main.js:163)), `exportCsv` ([main.js:2249-2278](web/src/main.js:2249)), and `SORT_COLS`/`SCHEMA` in [urlState.js:68-130](web/src/lib/urlState.js:68). The urlState test asserts a key *count* (27) but not membership. One missed edit silently misaligns every cell to the wrong header.

**M3 — MEDIUM — Cross-language and cross-file "keep in sync" contracts.** [fact]
- `historicalSlugify` in [main.js:1526-1534](web/src/main.js:1526) must match R's `slugify` in build_historical_shards.R "EXACTLY" (its own comment) or shards 404 silently.
- ~100 lines duplicated verbatim between [build_historical_shards.R](r/build_historical_shards.R) (`date_from_name` 85-89, `slugify` 93-99, `normalize_names` 103-108, `read_layer_repair` 115-138, neighbourhood binning 176-203) and [build_lineage.R:49-97](r/build_lineage.R:49), with an explicit "DUPLICATED … keep in sync" comment (build_lineage.R:26-27).
- `normalizeRoll` duplicated at [main.js:2709-2713](web/src/main.js:2709) and [soda.js:2340-2344](web/src/soda.js:2340).

**LOW — `parcel_search_app.R` is an orphaned legacy Shiny app** ([r/parcel_search_app.R](r/parcel_search_app.R)); nothing in the pipeline or docs references it. `extras/` is acknowledged scratch. [fact]

### 3.3 Code quality & correctness

**M4 — MEDIUM — Historical "gone" markers can be false after a partial fetch.** [fact]
`fetchCurrentAssessmentInBbox` ([soda.js:909-924](web/src/soda.js:909)) `break`s out of its paging loop on any non-OK response or thrown fetch and **returns the partial rows** (it correctly avoids *caching* partials, line 920-923, proving the author knew partials occur). `stampHistoricalSizeChanges` ([main.js:1746-1775](web/src/main.js:1746)) then classifies any historical roll missing from that partial set as `gone` → grey "roll not present in current data (removed / merged away)" popups ([map.js:2156-2158](web/src/map.js:2156)). A blip on page 3 of 10 falsely flags hundreds of parcels as removed, in a tool whose output feeds appraisal reports. The zero-overlap guard (main.js:1755-1763) only catches the 100%-loss case.

**M5 — MEDIUM — Sales mode: CSV export drops the sale columns; >500-roll CSVs are silently misreported.** [fact]
- `exportCsv` ([main.js:2249-2278](web/src/main.js:2249)) has a fixed property-mode header; none of the rendered sales columns (`_saleDate`, `_salePrice`, `_pricePerSf`, `_saleToAsmt`, `_dist`, instrument, etc.) are exported, though the Export button is enabled in sales mode.
- `runSalesAnalysis` joins every distinct roll into one query ([main.js:3109](web/src/main.js:3109)); `rollClause` silently `slice(0, 500)`s ([soda.js:2309](web/src/soda.js:2309)). Rolls 501+ then surface as synthetic "not in d4mq-wa44" rows ([main.js:3211-3231](web/src/main.js:3211)) — an *actively wrong* explanation. The 1,000-row `meta.truncated` flag is likewise never checked in sales mode.

**M6 — MEDIUM — `mapReady` hinges on a single `load` event the sister project documents as unreliable.** [fact that it's single-trigger; judgment on risk]
[map.js:300-301](web/src/map.js:300) resolves `ready` only from `map.on('load')`. [REFACTOR_NOTES.md:432-443](REFACTOR_NOTES.md) records MapLibre 4.x `load` "sometimes not at all (we saw 'never fires after 15 s' in dev)" and the multi-trigger + failsafe workaround the Manitoba app ships. If `load` never fires here, every `mapReady.then(...)` (searches still render the table, but map, overlays, and all toggles) waits forever with no error.

**LOW — Two CSV parsers.** A robust RFC-4180 parser exists at [soda.js:1617-1649](web/src/soda.js:1617) (contam registry); the sales tab uses a naive `split(',')` parser ([main.js:2961-2976](web/src/main.js:2961)) with a comment betting the City exporter never quotes. The bet may hold; the inconsistency is the smell. [fact]

**LOW — `wps_verify_v1:<roll>` localStorage keys grow unbounded** (one per parcel ever opened, never pruned) ([main.js:2177](web/src/main.js:2177)). Harmless for years; note it. [fact]

Error handling overall is a **strength**, not a gap — see 3.9.

### 3.4 Security

Healthy. No secrets in the repo (`VITE_SODA_APP_TOKEN` via env, optional — [soda.js:71](web/src/soda.js:71)); client-only app on public open data, no auth surface; popup HTML consistently escaped (`escapeHtml`, [map.js:1889](web/src/map.js:1889)) with a scheme-allowlist for external links from data (`safeExternalUrl`, [map.js:1676-1684](web/src/map.js:1676)); SoQL string inputs quoted-escaped ([soda.js:2220-2222](web/src/soda.js:2220)) against a read-only public API. Residual notes [judgment, Low]: basemaps/glyphs depend on free third-party tiers (Carto, Esri, demotiles.maplibre.org — [map.js:113-157](web/src/map.js:113)) whose ToS/availability you don't control; `npm install` (not `npm ci`) in [vercel.json:3](vercel.json) means deploys don't strictly honor the lockfile.

### 3.5 Testing

**M7 — MEDIUM — The tested 10% is tested well; the load-bearing 90% isn't.** [fact]
46 genuine behavioral assertions cover `urlState` (38 cases — malformed input, range, round-trip, schema invariants) and `sizeChange` (8 cases — thresholds, NaN/Infinity). Zero tests exist for the heart of the product's correctness: `parcelsOverlap`, `mergeSurveyFeatures`/`formatLotList` (the lot range-collapsing with partial markers), `rollClause`/`normalizeRoll`, `buildAddressClauses`, `zoningClause`, `dedupAndGroupSales`, `aggregateMidblockStudyRows` — all pure or near-pure functions in [soda.js](web/src/soda.js)/[main.js](web/src/main.js) that would have made the H1 regression or any join change visible. DOM-heavy lib modules (chipInput/columns/tabs/infoIcon) are untested but lower value-per-test. The test runner is plain `node test/*.js` — fine; the gap is coverage of pure logic plus **nothing executing `npm test` automatically** (no `.github/`, no CI of any kind — only Vercel's build-on-push, which doesn't run tests).

### 3.6 Performance

**M8 — MEDIUM — O(N×M) nested turf joins, bounded but quadratic.** [fact code; judgment severity]
`joinSurveyWithAssessment` ([soda.js:143-146](web/src/soda.js:143)), `joinAssessmentWithSurvey` ([soda.js:1724-1727](web/src/soda.js:1724)), `filterMatchedSurveys`/`filterMatchedAssessments` ([soda.js:1961-1992](web/src/soda.js:1961)) and `computePartialSurveyIds` ([soda.js:1994-2010](web/src/soda.js:1994)) each run `parcelsOverlap` (point-in-polygon) over the full cross-product, and a single assessment search executes several of these passes back-to-back. At the 1,000-row cap with dense back-fill that's millions of pip calls on the main thread. The bbox prefilter pattern already exists in-repo (`bboxesOverlap` used by zoning enrichment, [soda.js:355-357](web/src/soda.js:355)) — it just isn't applied to the joins. Fix only if large searches visibly jank (see Strategy).
Otherwise performance design is thoughtful: IndexedDB TTL caches for citywide zoning/traffic/contam/historical, memoised in-flight promises ([soda.js:642-667](web/src/soda.js:642)), per-feature bbox batching with parallel pages, vendor chunk splitting ([vite.config.js:17-27](web/vite.config.js:17)). `preserveDrawingBuffer: true` ([map.js:271](web/src/map.js:271)) is a deliberate, documented trade.

### 3.7 Dependencies

Healthy and lean: 9 runtime deps, all maintained, no known-CVE versions flagged in the lockfile review; the turf v7 API breakage is handled and documented ([soda.js:366-371](web/src/soda.js:366)). [Low, fact] `pmtiles.exe` (57 MB) is committed but nothing in the current pipeline invokes it (the Felt tippecanoe image writes `.pmtiles` directly per [Dockerfile.tippecanoe:5-6](Dockerfile.tippecanoe)); it's a leftover. The committed-artifact pattern for `web/public/*.geojson` (2-3 MB, reviewed diffs) is reasonable; the same pattern at 82 MB (parcels.pmtiles) is not — see H2.

- **No CI, no lint, no formatter** — nothing enforces anything ([fact]; folded into H1/M7 remediation).
- **Hardcoded `D:/Dropbox/...` absolute paths in every pipeline script** — [archive_snapshot.R:42-43](r/archive_snapshot.R), [build_historical_shards.R:50-52](r/build_historical_shards.R), [build_lineage.R:32-34](r/build_lineage.R), [build_parcel_tiles.R:34-38](r/build_parcel_tiles.R), [download_parcels.R:25-34](r/download_parcels.R), [sanitize_shards.R:17](r/sanitize_shards.R), [verify_shards.R:18](r/verify_shards.R), both `.ps1` runners, and [web/scripts/build-neighbourhoods-geojson.mjs:42](web/scripts/build-neighbourhoods-geojson.mjs). Plus a hardcoded `R-4.5.3` fallback path ([scheduled_download.ps1:15-16](r/scheduled_download.ps1)) that breaks silently on R upgrade. MEDIUM [fact] — acceptable for one machine, but it contradicts the replication-guide ambition and makes disaster recovery (new PC) a half-day of archaeology.
- **Scheduled tasks have no failure signal**: hidden window, log files nobody is prompted to read, "run as logged-on user" caveat documented only inside the script ([setup_schedule.ps1:20-34](r/setup_schedule.ps1)). MEDIUM [fact]
- **verify_shards.R / sanitize_shards.R are manual** — the build can publish unverified shards; verification exists but isn't wired into the build path ([build_historical_shards.R:420-423](r/build_historical_shards.R) writes index.json even when some snapshots failed). MEDIUM [fact]
- **Documentation**: REPLICATION_GUIDE.md is exceptional — architecture, every solved bug with symptom/cause/fix, SoQL reference. Inline comments throughout the JS explain *why* at a level rarely seen. Two corrections needed beyond H3: the guide's repo-structure section (§3) omits `lib/`, tests, and the historical pipeline (stale relative to code [fact]); REFACTOR_NOTES.md/WINNIPEG_PORT_KICKOFF.md describe the *Manitoba* repo and should be labeled as imported reference so a future reader doesn't hunt for `arcgis.js` here.

### 3.9 Strengths (preserve these)

1. **Failure-tolerant UX wiring**: every overlay toggle optimistically flips, then rolls back button/aria/layer state on fetch failure ([main.js:768-779](web/src/main.js:768) and siblings); enrichment failures degrade to partial rows instead of blank tables ([soda.js:256-266](web/src/soda.js:256)).
2. **Race-condition discipline**: monotonic load tokens for historical loads ([main.js:1510-1514](web/src/main.js:1510)) and sales runs ([main.js:2692](web/src/main.js:2692)); memoised in-flight promises that clear on rejection ([soda.js:664-666](web/src/soda.js:664), [soda.js:1688-1693](web/src/soda.js:1688)).
3. **Self-invalidating cache design**: historical cache keys embed the pinned CDN SHA ([soda.js:827-836](web/src/soda.js:827)) — republish = automatic client refetch, no manual version bumps.
4. **Paging with truncation semantics**: user searches cap loudly (`meta.truncated` → "Showing first N…"), internal queries *throw* rather than silently accept partial joins ([soda.js:2196-2198](web/src/soda.js:2196)).
5. **Provenance sidecars** on every archived dataset (hash, CRS, schema, license — [archive_snapshot.R:137-179](r/archive_snapshot.R)) — appraisal-grade defensibility.
6. **Encoded geometry lessons**: bidirectional centroid containment ([soda.js:1803-1806](web/src/soda.js:1803)), within_box padding, edge dedup + canonical keys, condo geometry-hash dedupe with `_unitCount` popups ([main.js:1221-1250](web/src/main.js:1221)).
7. **XSS hygiene and a11y basics** (escaping, scheme allowlist, aria-pressed/aria-live/keyboard nav) done without a framework.
8. **The dataset registry** ([r/wpg_datasets.R](r/wpg_datasets.R)) as single source of truth for the download/archive pipeline — exactly the right pattern; extend it, don't bypass it.

## 4. Improvement Strategy

### Theme A — "Make the repo tell the truth" (identity, history, hygiene)
Findings: H2, H3, `.tmp.*` litter, Dropbox-git corruption.
**Target state:** README/LICENSE describe *this* project under your chosen license; git history < 30 MB; binaries live outside history (rebuilt artifacts or LFS/release assets); `.git` no longer syncs through Dropbox.
**Principle:** the repo is the product's memory — it must be cheap to clone and impossible to misread.

### Theme B — "No silent failure" (reliability + automation)
Findings: H1, M4, M6, no CI, pipeline exit codes, push-unchecked.
**Target state:** retry restored; CI runs `npm test` on every push and fails the build; partial fetches can never masquerade as complete data; scheduled scripts abort the destructive step on any upstream non-zero exit and leave a loud marker on failure.
**Principle:** every failure either retries, surfaces to the user, or halts before the destructive step — never proceeds quietly.

### Theme C — "Protect the correctness core with tests, not comments"
Findings: M7, H1 (root cause), M2/M3 (sync contracts).
**Target state:** the pure functions that define product correctness (joins, merges, roll/zoning clauses, sales dedup, slugify parity) have direct unit tests in the existing plain-Node style; the column contract has a single registry (or at minimum an assertion test that thead order == renderTable order == SORT_KEYS == export header); R helpers are `source()`d from one file; slugify parity is asserted by a fixture test.
**Principle:** anywhere the code says "keep in sync" or "order MUST match", a test should say it instead.

### Theme D — "Calibrated structure, not a rewrite"
Findings: M1, M8.
**Target state:** main.js sheds its two self-contained features (sales tab → `src/sales.js`, historical overlay → `src/historical.js`) along the seams that already exist; the O(N×M) joins get the in-repo bbox prefilter *only if* profiling shows jank. No framework, no TypeScript migration, no test-runner swap.
**Principle:** match structure to a one-maintainer tool — extract along existing seams, decline speculative architecture.

### Explicitly NOT recommended (effort vs. payoff at this maturity)
- **No React/TS/framework migration** — the no-framework approach is working and well-executed.
- **No DOM-module test coverage push** (chipInput/tabs/infoIcon) — low defect history, high test cost; rely on manual smoke.
- **No e2e/browser test harness** — overkill for one maintainer; the preview-verify workflow covers it.
- **No coverage-percentage target** — test the named correctness core, not a number.
- **No fixing** the two-CSV-parser inconsistency, localStorage growth, or `window._map` exposure unless touched anyway.
- **Dropped** (decision 4): the O(N×M) join optimization — performance feels fine in real use and the 1,000-row cap bounds the worst case. Revisit only if a slow search is actually observed; the fix (bbox-prefilter via the existing `bboxesOverlap`) is documented at finding M8.

### Definition of done — measurable signals
1. `git clone` of a fresh copy ≤ 30 MB and < 30 s; zero files > 5 MB in history.
2. CI badge green; a PR that breaks `npm test` cannot merge (or at minimum, visibly fails).
3. README first line names the Winnipeg Parcel Search; `LICENSE` is yours; go-pmtiles attribution moved next to the tool it covers (or the exe removed).
4. `fetchSoda` retries 5xx/network ×2 with backoff (test exercises it with a stubbed fetch).
5. Pipeline: every write is temp-file + rename; `scheduled_download.ps1` aborts before cleanup on any non-zero exit; `refresh_assets.ps1` fails loudly on push failure; verify step runs inside the build script.
6. Zero false "gone" markers possible: partial current-assessment fetches either throw or disable size-change stamping.
7. New-column smoke: adding a test column requires edits in ≤ 2 places or a failing test tells you the third.

Approach: `git show 559f4f8:web/src/soda.js` and lift the old `fetchSoda(url, { retries = 2, retryDelayMs = 1200 })` body verbatim (loop attempts 0..retries; on `res.status >= 500 && attempt < retries` → warn + `setTimeout` backoff `retryDelayMs * (attempt+1)` + continue; on `err instanceof TypeError` same; 4xx throws immediately). Gotchas: (a) the current file has no other callers passing options — signature change is backward-compatible; (b) keep the error text format `SODA ${status}: ${body.slice(0,200)}` — `runLegalSearch`/`runAssessmentSearch` surface it to users; (c) test by injecting `globalThis.fetch` stub in plain Node (no framework needed — the existing test files show the pattern); (d) note in the test file *why* it exists (the 1348c06 regression) so a future simplify pass keeps it.

**2.1 Repo slimming.**

## 6. Decisions (open questions resolved with Jason, 2026-06-10)

1. **License** — repo is/will be **public**. Plan adopts **MIT** for task 1.2 (conventional default for a small public tool; swap to Apache-2.0 at implementation time if patent language is wanted). 2. **History rewrite is safe to schedule** — Vercel deploys from GitHub `main`; no other clones known. Task 2.1 risk drops from High to Medium (sole contributor, bundle backup, single deploy linkage).
3. **Sales CSVs do sometimes exceed 500 rolls** — task 3.1 is upgraded from "warn" to **chunked batching** (see revised 3.1).
4. **Performance feels fine** — former task 3.8 (bbox-prefilter the O(N×M) joins) is **dropped**, moved to the not-recommended list. Revisit only if a slow search is actually observed.
5. **`pmtiles.exe` deletion confirmed safe** — verified by grep: nothing in the repo invokes it (the only mentions are the misplaced README and two comments explaining the convert step is *not needed*: [Dockerfile.tippecanoe:6](Dockerfile.tippecanoe), [build_parcel_tiles.R:174](r/build_parcel_tiles.R)). It's re-downloadable from go-pmtiles releases and lands in the 0.2 backup bundle regardless. With the exe gone, no `THIRD_PARTY_LICENSES.md` is needed — the Protomaps text simply leaves with it.

See revised 3.4.
